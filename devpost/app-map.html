RepoMind AI

Upload a JavaScript or TypeScript project and follow its local imports into a visual architecture map. Select a node to inspect its source and connections, then copy the graph as Mermaid.

Runs locally in your browserGemini key stays server-sideProject files are not saved between visits

One action through the app

The demo button follows the same client-side path as an uploaded folder or ZIP. The selected module can optionally be summarized by Gemini through a server route.

Reference code route

Use these three stops to find where the visible upload-to-inspection flow lives. This is a reference route, not a claim that the source was toured interactively.

01 / INPUT

src/app/page.tsx

Start at startParsing and handleDemoRepo. They receive files, update loading state, and set the project graph after parsing.

02 / TRANSFORM

src/lib/parseProject.ts + architecture.ts

parseProjectFiles reads source text. buildArchitectureGraph classifies files and resolves local imports into edges.

03 / RESULT

GraphCanvas.tsx + NodeInspector.tsx

GraphCanvas renders and selects nodes. NodeInspector shows connections, source, and a server-generated summary or local fallback.

AI summary behavior

route.ts: model request and completeness guard. Set the key in ignored .env.local; never paste a real key into the example file.

Mermaid output and copy feedback

generateMermaid.ts creates the diagram; handleMermaidExport in page.tsx copies or downloads it.

A practice to reuse

A successful HTTP response did not guarantee a useful summary: an early Gemini response was cut off mid-sentence. The live output check exposed it; reducing thinking effort, increasing the output ceiling, and rejecting incomplete answers produced a complete result while preserving the fallback. For another AI feature, verify the content users see, not just the request status. The implementation is in the summary route; the discovery is recorded in the build revisions.

Run it again

From the repo-mind-ai directory:

npm install
npm run dev

Open http://localhost:3000. Gemini summaries require a valid server-side GEMINI_API_KEY; otherwise the local fallback remains available.
